# Restaurant ERP System Project Rules

## Mandatory Language Requirement (High Priority)
- The Restaurant ERP System must be an English-only website.
- All user-facing content must be in English, including navigation, page titles, buttons, tables, forms, validation messages, notifications, and error messages.
- All code identifiers, comments, database fields, and project documentation must also use English.
- Do not add Chinese text or multilingual functionality to the website unless explicitly approved by the user.

## Current Project State
- Step 3 implementation of the first approved inventory website prototype is complete.
- Browser acceptance testing is complete as reported by the user; Codex did not independently rerun those browser tests.
- Step 4 requirements gap analysis is complete.
- The approved prototype uses plain HTML, CSS, vanilla JavaScript, and localStorage, without a framework, external dependencies, backend, or database integration.
- REQUIREMENTS.md records implemented scope, business rules, acceptance evidence, and limitations.
- First-week final acceptance criteria, submission format, and deadline remain unconfirmed. User-reported prototype acceptance does not establish internship supervisor approval.

## Overall Project Direction
- Manage restaurant ingredient quantities, daily incoming stock, daily consumption, and remaining stock.
- The full ERP plan includes a backend database, a frontend website, PDF invoice uploads with AI extraction into the database, business metrics, and forecasting.
- These longer-term plans are separate from the approved prototype and are not automatically required in the first week.

## Scope and Working Method
- Work one small approved step at a time. Report the result and wait for user approval before continuing.
- Do not add features or invent requirements without explicit user approval.
- Follow the scope and restrictions of the current user-approved step. Application changes are allowed only when authorized for that step.
- Obtain user approval before introducing new technical choices, frameworks, dependencies, backend or database integration, or deployment.
- Preserve approved inventory rules and the English-only requirement in future changes.
- Identify missing information rather than assuming business rules.
- Explain work clearly for a beginner. Conversation replies may use simple Chinese as requested by the user; project documentation must use English.

## Testing, Reporting, and Stopping
- After future code changes, perform available syntax and relevant functional checks; report PASS, FAIL, or NOT TESTED for each check.
- Distinguish independently executed checks from user-reported results. Never claim an unexecuted check passed.
- Check consistency with approved scope and requirements, and report all changed files and material limitations.
- For documentation-only steps, verify documentation consistency and confirm application source files remain unchanged.
- Stop after completing the authorized step and wait for approval before proceeding.
